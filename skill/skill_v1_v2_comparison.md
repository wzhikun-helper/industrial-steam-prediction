## 3. Skill v1 发现的问题

### 问题 1：RMSE 汇总方式不一致

Notebook 第 8 章曾采用：

```text
sqrt(mean(fold MSE))
```

而项目主要实验及 `src/evaluation.py` 使用：

```text
mean(sqrt(fold MSE))
```

这导致 KFold RMSE 出现：

```text
0.336066
```

与：

```text
0.335365
```

两种结果。

虽然差异很小，但会造成同一项目评价指标定义不一致。

### 问题 2：功能测试与正式实验评估没有明确区分

v1 中部分临时测试只是为了检查：

- 模型能否运行；
- 输出维度是否正确；
- 是否存在 NaN；
- 不同模块能否正常连接。

但 v1 没有明确说明这些结果不能直接用于论文中的正式性能比较。

这可能导致临时测试结果与正式实验结果混淆。

## 4. Skill v2 的主要修改

### 修改 1：统一 RMSE 定义

Skill v2 明确规定交叉验证 RMSE 统一采用：

```text
mean(sqrt(fold MSE))
```

即先计算每一折 RMSE，再对所有折求平均。

同时要求正式实验统一使用：

```python
summarize_cv_scores()
```

进行汇总。

### 修改 2：区分测试类型

Skill v2 新增：

```text
测试类型：功能测试
```

以及：

```text
测试类型：正式实验评估
```

功能测试只用于验证程序流程。

正式实验评估才用于：

- 模型比较；
- 调参；
- 模型选择；
- 融合权重选择；
- 论文结果。

### 修改 3：强化实验控制变量

模型比较、特征处理比较和验证策略比较时，需要保持除待比较因素以外的其他条件一致。

### 修改 4：明确 SHAP 解释对象

当前 SHAP 解释对象明确为：

```text
Best XGBoost
```

不能直接描述为对 Ridge + XGBoost 加权融合模型的解释。

### 修改 5：强化融合评估约束

融合权重选择和最终性能评价不能使用同一批数据。

当融合提升幅度很小时，需要如实描述，不夸大改进。

### 修改 6：完善最终输出检查

最终输出需要检查：

- 预测样本数；
- NaN；
- 模型文件；
- 融合配置；
- 结果文件；
- 提交格式。
